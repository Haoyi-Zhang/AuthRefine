transfer. The original five-of-nine frozen and nine-of-nine adapted results
remain unchanged. This followup addresses exactly the other sixty selected
entry bindings: 58 concrete source-functional contracts and two abstract

The concrete contracts cover Baserow (4), Taiga (17), Recipes (28), Horilla (4),

## What is checked

`contracts.py` contains separately written reference equations. Each input
contract binds repository, original commit, module and complete entry body,
normal data, entry premises, expected return identity or named error/status/code,
specified effects and dependency-call arguments,counts/order. `profiles.py` supplies
explicit owned lookup/query/credential primitives. `interpreter.py` reads source
AST as data, using bounded typed values, not imports, eval or application
bytecode. `observations.py` preserves value types and checks exact dependency
handoffs: a different object,token,permission label,query filter or cache scope does not pass
merely because it produces the same Boolean. Tuple/list and Boolean/integer
observations are distinct. Empty reference domains and duplicate entries cannot
be counted as completed contracts. Unsupported setup and exhausted budgets
remain unknown; setup errors do not count as detected semantic controls.

The Dify prefix classifier and UTF-8 digest wrapper now use complete pinned
source bodies. The classifier reads the three original literal enum values and
prefixes through a bounded string-enum interface; it does not execute enum class
initialization or infer subject policy. Legacy input selectors choose owned
token strings,not classifier output. A single configured account resolver and
its lookup row remain explicit. Other recognized prefixes are distinguished
from unknown prefixes without silently adding a resolver. Composite Taiga
components must receive the exact request,view and object even when their
supplied decisions happen to be identical.

Argilla's returned user is a source-bound UserInfo projection,not a plain
mapping. It retains the claims remaining after scope extraction and the actual
source authentication property. Its dict-copy construction and property
descriptor are checked against the original class;claim keys cannot shadow
that descriptor. Role/environment properties,unconsumed dynamic attributes
and full framework dispatch are not inferred from this entry observation.

Same-module permission helpers and fixed superclass bodies are retained.
The original preview route-ID parser and employee-company resolver are now
interpreted,not supplied as resolved values. The resolver's exact import binds
an explicit owned query interface without invoking a host module loader. Its
query target,column,superuser short circuit and failure path are checked.
Imported user-source claim and operation literals are read from the pinned
original definitions,not replaced by representative labels. Cache keys,values,
defaults and expiry arguments are checked together.
Return identities, tenant selection and request state are observed. Share saves
are read back from an owned SQLite store; repeated reads check cache behavior.
Open WebUI's scheduled JWT activity is distinguished from awaited API-key
activity. Preview route parsing and its failures retain the actual
401/APIException error mapping. Every selected helper body has an exact source
identity binding. Baseline state is checked on denials as well as successes.
Owned controls omit save, cache or tenant selection, or alter identity equality;
normal-input observation differences must detect each control. No upstream
application, upstream test, service or exploit is executed.

These are finite source-functional references under explicitly supplied
dependencies, not independently reviewed policy-intent gold. They establish
neither cryptographic correctness, full ORM/framework dispatch, deployment nor
new upstream vulnerabilities. The original prospective outcomes stay separate.
